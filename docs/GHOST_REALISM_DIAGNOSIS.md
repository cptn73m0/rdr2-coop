# Диагностика: реалистичность педа-призрака (read-only)

Цель: добиться, чтобы пед-призрак (визуальная копия удалённого игрока) не
«выбивался» из игры — двигался, стоял, целился и ездил так же естественно,
как настоящий игрок рядом. Первый шаг — сделать «неестественность»
**измеримой**, потом чинить точечно.

## Текущий механизм (факт из кода, ветка origin/main @ 11caffe)

Пед-призрак — это **автономный актор**, которого ведут задачей навигации, а не
точная реплика позы хозяина.

| Слой | Функция | Механизм |
|---|---|---|
| Применение кадра | `ApplyRemoteFrame` → B1..B4 | диспетчер фаз (Early/Mount/Position/VisualTail) |
| Локомоция | `ApplyMoveToGhost` (5494) | `TASK_FOLLOW_NAV_MESH_TO_COORD`, скорость анимации `SET_PED_MAX_MOVE_BLEND_RATIO` hard-coded 1.0 (шаг) / 2.0 (бег) |
| Догон | `ApplyRemoteFramePositionPhase` (4176) | телепорт при dist>12 (бег)/dist3>10 (idle); спринт-догон >6 м/застрял; бег-догон >4 м (idle) |
| Поворот | `ApplyRemoteFrameVisualTail` (4353) | heading-lerp 0.2, мёртвая зона 5° |
| Идл | тот же position-phase | `TASK_STAND_STILL`, ground-fix при подвесе >2.5 м (раз/сек) |
| Верх | `ApplyRemoteFrameMountPhase` + `MoveMountTo` | пед сажается на лошадь-копию; лошадь ведётся `TASK_FOLLOW_NAV_MESH` отдельно |
| Оружие | `ApplyActionToGhost` (aim/shoot) | `TASK_AIM_GUN_AT_COORD` (time=-1), `TASK_SHOOT_AT_COORD` SingleShot |

## Что уже есть для измерения (Build the Lever)

- `npc_debug` в `rdr2-coop.ini` → каждые 300 тиков лог `perf: frame host/guest
  tick=.. p95.. world.. actor.. coop.. frames_hz=.. tick_hz=..`.
- `g_frameSentWindow` → фактическая частота отправки кадров (`frames_hz`).
- Маркеры `coop:` (98 шт.): `move change %u->%u`, `ghost teleport (move/idle)`,
  `recv move=.. state=.. at / cur`, `mount lag/teleport/settle`.
- `tools/perf_report.py` — агрегация perf-лога.

## Чего НЕ хватает для диагноза «дёрганья» (пробел)

1. **Частота retarget** задачи движения (`ApplyMoveToGhost`, порог 0.25 м) — не
   измеряется. Частые retarget = визуальный «подхват»/дёрганье.
2. **Частота ground-fix** (SetEntityCoords при подвесе) — не измеряется.
3. **«Недохаживание»** педа (cur vs target в момент гашения задачи) — не меряется.
4. **Частота смен move за окно** (Walk↔Idle↔Run флаппинг) — нет агрегата, только
   построчный `move change`.
5. **Частота телепортов за окно** — логи есть, но нет счётчика за единицу времени.
6. **Рассинхрон всадник↔лошадь** (дистанция пед↔седало лошади при Seated) — не меряется.

## Гипотезы причин «выбивания» (по приоритету)

- **H1 (главная): gait не реплицируется.** Пед получает только enum move
  (Walk/Run), а реальный аллюр (красться/полушаг/рысь/спринт) хозяина теряется;
  `SET_PED_MAX_MOVE_BLEND_RATIO` ставит жёсткие 1.0/2.0 → пед «шагает по-своему».
- **H2: автономный навмеш, а не фоллоу траектории.** `TASK_FOLLOW_NAV_MESH` строит
  свой путь; при обходе препятствий пед расходится с хозяином, затем телепорт/спринт.
- **H3: нет pitch/roll.** На склонах/лестницах пед «стоит столбом» и виснет → ground-fix.
- **H4: прицел/оружие «робот».** Мгновенная наводка без угловой скорости/тремора.
- **H5: верх = два независимых актора.** Лошадь и всадник ведомы разными задачами,
  рассинхрон.

## План измерений (как диагностировать, не меняя поведения)

Шаг D1 — **счётчики-гистограммы в HUD/log** (read-only, только лог, `npc_debug`):
- `retarget/s` (частота постановки TASK_FOLLOW),
- `groundFix/s`,
- `teleport/min` (уже есть события — агрегировать),
- `moveFlap/s` (флаппинг Walk↔Idle↔Run за окно),
- `mountDesync` (дистанция пед↔лошадь при Seated, avg/max).

Добавить их в существующий perf-блок (6840–6886) рядом с `frames_hz`, за теми же
`s_npcDebug`. Это измеримый baseline.

Шаг D2 — **ручной прогон + capture** сценариев, где пед «выбивается»:
- ровная дорога: хозяин идёт → пед идёт (gait совпадает?),
- змейка/обход камня: расходятся? телепорт?
- лестница/склон: наклон, провисание, ground-fix,
- стрельба по бегущей цели: скорость наводки,
- верх: посадка, повороты, спешивание — рассинхрон?

Снять snапшот лога `coop:*.log` + `perf:` за каждый сценарий.

## Критерий готовности диагностики

После D1+D2 у нас есть числовые baseline'ы для H1–H5, и каждый следующий фикс
доказывается **дельтой** этих счётчиков (retarget/s ↓, moveFlap/s ↓, mountDesync ↓,
gait совпадает по eyeball/видео). Без измерения не чиним.

## Следующие шаги (после диагностики)

- P1: репликация gait (`GET_PED_DESIRED_MOVE_BLEND_RATIO` на отправителе →
  `SET_PED_DESIRED_MOVE_BLEND_RATIO` на получателе вместо hard-coded 1.0/2.0).
- P2: pitch/roll (осторожно, протокол).
- P3: фоллоу траектории (цель = позиция + опережение по heading).
- P4: дебаг idle-jitter (по счётчикам D1).
- P5: верх как единый акт.
- P6: «человечность» прицела.
