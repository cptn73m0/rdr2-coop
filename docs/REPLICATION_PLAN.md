# План улучшения репликации — RDR2 CO-OP

Цель: сделать воспроизведение мира/состояния удалённого игрока (педа-призрака)
у хоста/гостя более «реалистичным» — плавным, без рывков, с точными позами и
событиями, при минимальном трафике.

Текущая модель — снэпшот-протокол: `GhostFrame`/`FramePayload` шлётся по таймеру,
сервер ретранслирует, получатель применяет кадр сразу. Уже есть: heading-интерполяция
(`LERP_FACTOR=0.2`), мёртвые зоны, дебаунсы move, фазовая машина верховой езды,
событийный выстрел (`Shot`). Слабые места: нет буферизации по `seq`, нет интерполяции
позиции, нет экстраполяции, единая частота на всё, отсутствуют pitch/roll/скорость.

## Ограничения

- `FramePayload` жёстко зафиксирован `static_assert(sizeof == 88)`; сервер проверяет
  `pay.size() >= sizeof(FramePayload)` (см. `server/server.cpp`, `docs/PROTOCOL.md`).
- Любое изменение провода = парный деплой ASI + server + обновление `PROTOCOL.md`
  + прогон `scripts\ci.ps1` (41/41). Без этого клиент A не поймёт клиента B.
- Порядок строго последовательный; каждый пункт = отдельный коммит (why/what/proof).

## Детали по пунктам (кратко)

### 1. Интерполяция позиции
Ring-buffer снэпсов на получателе (`{seq, pos, heading, rxMs}`, ёмкость 4). В `Tick()`
рендерим цель = lerp двух последних снэпов с отставанием ~100 мс. Телепорт
(`> TELEPORT_DIST`), смерть, ragdoll — сброс/мимо буфера. Менять только `src/coop.cpp`.

### 2. Экстраполяция
Скорость из двух последних снэпов. Если свежего кадра нет — продлеваем позицию по
скорости, лимит ~250 мс, далее снаппинг. Плавный сброс при восстановлении.

### 3. Раздельная частота
Сетка: позиция/поворот ~20–30 Гц; health/state/flags/move ~10 Гц или по смене;
прицел ≥30 Гц только при целится/стреляет, иначе редко; остальное по смене (уже так).

### 4. Дельта-кодирование
`u32 fieldMask` перед полезной нагрузкой. Только изменённые поля. Получатель мержит
в state-аккумулятор. Сервер ретранслирует как есть, но хранит полное состояние для
`PLAYER_JOINED`. Абсолютный (baseline) кадр раз в ~1 с. Нужно версионирование.

### 5. События
Новые `Msg::*`: `WeaponChanged`, `ScenarioStarted/Ended`, `ReloadStarted/Done`
(опц. `SpeechEvent`). Только краткие дискретные вещи, которые состояние не ловит.
Выстрел уже сделан правильно (`Shot`) — эталон паттерна.

### 6. Pitch/roll + скорость
A) без изменения размера: скорость из разности (п.2), pitch квантованный в свободный
байт (`pad0`/`reserved`).
B) расширение `FramePayload` (~96–100 б): `vx/vy/vz`, `pitch/roll` (int8), horse-speed;
обновить `static_assert`, сервер-проверку, `PROTOCOL.md`, парный деплой.
