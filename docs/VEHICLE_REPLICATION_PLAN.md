# План: репликация повозки как транспорта (вместо «скользящего прокси»)

Цель: убрать артефакты репликации повозок/дилижансов у гостя. Сейчас повозка —
это «прокси-объект без физики» (CREATE_VEHICLE + noCollision + ручная
интерполяция позиции), поэтому она скользит по дороге, колёса не вращаются,
лошади и кучер «приклеены» и дёргаются.

## Текущий механизм (факт из src/world_sync.cpp)

- Прокси-vehicle создаётся `CREATE_VEHICLE(model, x,y,z,heading, isNetwork=false,
  bScriptHostVeh=false, bDontAutoCreateDraftAnimals=TRUE, ...)` — тягловых
  лошадей движок не плодит, чтобы не дублировать с репликой.
- `SetNoCollision(true)` + `SetInvincible(true)` + `SetMissionEntity` — прокси
  декоративный, физики/колёс нет.
- Позицию двигает `InterpolateVehicleProxies` (60 Гц, ручной lerp к цели из
  WorldSnapshot) — отсюда «скольжение».
- Кучер/draft-лошади прицепляются отдельно через `VehicleOccupants` (0x21),
  `draftAttached`/`harness` — педы «приклеиваются» к прокси.

## Проблема (то, что видит пользователь)

- Повозка скользит (нет вращения колёс, нет качания на рельефе).
- Лошади/кучер «как приклеенные» — дёргаются, рассинхрон.
- Нет нативного поведения транспорта (физика, подвеска, тяга лошадей).

## Предлагаемое решение (по запросу: «спавн транспортом + команды кучеру»)

Идея — вместо «декоративного прокси, двигаемого вручную» создать на госте
**настоящий транспорт с тягловыми животными** и передавать кучеру **команды
управления** (а не позицию), чтобы движение, колёса, тяга и посадка работали
нативно движком.

### Подход A — нативный транспорт + автопилот кучера

1. **Спавн транспорта с тягловыми животными** как единой единицы:
   - `CREATE_VEHICLE(..., bDontAutoCreateDraftAnimals=FALSE)` — пусть движок
     создаст тягловых лошадей нативно (кобыла/упряжка).
   - Не `SetNoCollision` (нужна физика колёс/подвески).
2. **Кучер-автопилот**: вместо ручного `SetEntityCoords` прокси — дать
   кучеру-педу задачу управления (`TASK_VEHICLE_DRIVE_WANDER`/`_TASK_VEHICLE_-
   DRIVE_TO_COORD` или navmesh-follow), чтобы повозка двигалась нативно.
3. **Команды от оригинала**: хост шлёт не позицию, а **intent движения**
   (вперёд/стоп/поворот, скорость, target-coord) кучеру гостя.

### Подход B — гибрид (минимально-рискованный первым шагом)

Оставить `WorldSnapshot`-репликацию, но:
1. Снять `SetNoCollision` и дать прокси **физику** (колёса крутятся, рельеф).
2. Драфт-лошадей сажать **на позицию тяги нативно** (не «приклеивать» педами
   вручную), а через `SET_PED_ONTO_VEHICLE`/attachment к шарниру упряжки.
3. Кучера вести задачей движения (а не телепортом), чтобы он «правил»
   повозкой нативно.

### Ключевые нативы (проверить в rdr3-nativedb перед кодом)

- `CREATE_VEHICLE` — уже есть (с draft-флагом).
- `TASK_VEHICLE_DRIVE_WANDER` / `_TASK_VEHICLE_DRIVE_TO_COORD` — задача вождения
  (заменить ручную интерполяцию прокси).
- `SET_PED_ONTO_VEHICLE` / `SET_PED_INTO_VEHICLE` + attachment — нативная посадка
  кучера/draft-лошадей.
- `SET_VEHICLE_FORWARD_SPEED` / `SET_VEHICLE_ON_GROUND_PROPERLY` — нативное
  движение транспорта (заменить SET_ENTITY_COORDS).

## Объём и риски

- Это **крупный рефакторинг** `world_sync.cpp` (прокси-vehicle путь) +
  `actor_sync` (draft/occupant attach) + возможно `natives.h` + `PROTOCOL`
  (если надо новый intent-сообщение для «команд кучеру»).
- Риск: нативная посадка/тяга лошадей в RDR2 чувствительна к модельному кэшу,
  билду 1.0.1491.50; нужна нативная разведка (как для crouch/stealth).
- Оценочно — это отдельная задача уровня `E3d-c` (occupants) или больше.

## Рекомендация по порядку

1. Сначала — **нативная разведка** (driving tasks, vehicle physics-нативы,
   draft-посадка) по `rdr3-nativedb`, как сделано для crouch/stealth, и
   зафиксировать в `docs/NATIVE_RESEARCH_VEHICLE.md`.
2. Затем — **Подход B** (гибрид, минимально рискованный): физика + нативная
   посадка, не трогая протокол. Проверка в игре.
3. Финал — **Подход A** (полный, команды кучеру), если B дал хороший результат
   и нужна ещё бОльшая нативность.
