## 4. Приоритеты

### P0. LICENSE + NOTICE (0,5 ч)
Без этого порт MIT-кода невозможен. Заодно закрывает давнюю дыру репозитория.

### P1. Ambient-профили: зачистка лагерей (2–4 нед)
Почему сейчас: у нас уже есть весь транспорт — actor-спавн, кадры, урон интентом,
трупы, cleanup. Не хватает четырёх вещей:
1. **Детектор события**: хост распознаёт начало зачистки (по каталогу профилей, а не
   по «любым враждебным педам») — их `BridgeOwnedEncounterCatalog` как образец.
2. **Ростер**: хост создаёт фиксированный состав бойцов (модели/позиции/оружие) и
   рассылает его как authoritative-спавн, вместо зеркалирования случайной популяции.
3. **Подавление дубля**: у гостя в радиусе не должно быть своей версии этого лагеря.
4. **Завершение**: успех/провал/уход по дистанции/дисконнект → уборка через 30 с;
   награды, Honor, лут — не копируются (их политика корректна).

Нужен bump протокола: **v23** (`EncounterOffer/State/Roster/Damage` можно собрать
из существующих 0x18–0x1F, но чище — отдельные типы). Деплой парный: ASI + server.

Критерий приёмки: два ПК заходят в один лагерь; гость видит тот же состав; урон гостя
убивает NPC хоста и наоборот; у гостя нет второй войны рядом; уборка на всех выходах.

### P2. Downed/revive (2–4 дня)
Сейчас смерть = respawn. Их модель: «ранен, ползёт», товарищ держит E 4 с в радиусе 2 м,
восстановление 35% HP, валидация хостом, авто-ретрая нет. Требует 1 сообщение
(`PlayerDowned`/`PlayerRevive`) + состояние в кадре. Даёт наибольший прирост «коопности»
на единицу работы.

### P3. Live mirror (3–5 дней)
Один процесс игры + loopback-гость: реплика рядом с игроком и «Co-op view» для мира.
Снимает главный блокер: сейчас каждый тест = два ПК и человек. Их реализация
подтверждает, что это работает без второго процесса.

### P4. Пароль сессии + лаунчер (1–2 нед)
Для публичного мода: пароль в JOIN (у нас уже есть причины отказа), авто-подбор сервера
в LAN, установка/удаление по манифесту, гейт версии игры, guard от RDO.

### P5. Позже
Пульсы действий NPC, сверка сценариев, поезда, чат, диагностика.

## 6. Ограничения и риски

- **Двух-ПК валидации у них нет**: их STATUS прямо пишет, что ambient/миссии/reward
  на двух машинах не проверены. Их «реализовано» = «собрано и покрыто self-тестами»,
  а не «работает в игре». Наши приёмки должны быть игровыми, а не по логам.
- **Протокол**: любое новое сообщение = v23 и парный деплой ASI+server; иначе
  `VersionMismatch` у игроков со старым клиентом.
- **Детерминизм**: AI/физика/катсцены не совпадут; профили дают общий бой, но не
  кадр-в-кадр.
- **Nexus/юридика**: MIT-код можно; ScriptHook/dinput8 в релиз не бандлить (уже
  нарушено в `v0.1.0` — отдельная задача).
- **Наш техдолг**: `coop.cpp` 418 КБ и `world_sync.cpp` 213 КБ — любые вставки
  усложняют поддержку; новые фичи лучше выносить в отдельные файлы.
