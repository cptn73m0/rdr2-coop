# RDR2 CO-OP — кооперативный мод для одиночного сюжета

Кооперативный мод для **Red Dead Redemption 2** (Story Mode), позволяющий двум
игрокам играть по сети в одиночный сюжет. Каждый проходит миссии сам у себя,
а второй игрок виден как **призрак-наблюдатель** (его пед отображается рядом),
с синхронизацией местоположения, поворота, состояния, внешнего вида, лошади,
действий, а также времени и погоды.

## Статус

Рабочий прототип, проверено в игре двумя игроками (билд **1.0.1491.50**):

- ✅ Плагин `.asi` загружается и регистрируется в ScriptHookRDR2.
- ✅ Пед удалённого игрока создаётся, рендерится, следует за своей позицией
  (не зеркалит локального игрока); плавная интерполяция движения.
- ✅ Сетевой слой: сервер-релей + клиент в плагине; реальный JOIN, FRAME,
  LEAVE, Died, WorldState, Outfit.
- ✅ Позиция, поворот, локомоция (стоит/идёт/бежит/верхом) — синхронизируются.
- ✅ Особые состояния: укрытие, плавание, лестница, прыжок, падение, ragdoll.
- ✅ Действия (первая итерация): сценарий/сидение/пьян, стрельба, перезарядка.
- ✅ **Одежда**: надетые shop-предметы (рубашка, шляпа, патронташ, кобура…)
  передаются отдельным сообщением и применяются к педу-призраку.
- ✅ **Верховая езда**: лошадь-призрак (модель из кадра), посадка педа; лошадь
  без коллизий (нет вылетов при конфликте с чужим транспортом).
- ✅ **Время и погода** от хоста: хост шлёт часы+погоду, остальные применяют.
- ✅ **Бессмертие** педа-призрака: умирает только вместе с оригиналом; труп и
  снаряжение остаются лежать.
- ✅ Имя игрока над головой педа (предел дальности), метка на карте/мини-карте.
- ✅ Персистентность последней позиции (новый игрок — рядом с хостом; повторный
  — на его последних координатах; спавн сразу на земле, без падения).
- ✅ Конфиг `rdr2-coop.ini`: адрес/порт сервера, ник, модель персонажа.
- ✅ Сервер в окне консоли: логи подключений с IP, таблица состояния игроков.

В плане: детальные анимации сценариев, снаряжение лошади (седло/уздечка),
интерполяция/сглаживание, игра через интернет.

## Идея мода

- **Сюжет** каждый игрок проходит сам у себя.
- **Второй игрок** виден как следовающий за ним наблюдатель-«призрак» с полной
  синхронизацией: позиция, поворот, движения, особые состояния, одежда,
  оружие, лошадь, действия; время и погода общие (от хоста).
- При повторном входе игрок спавнится на координатах, где был при последнем
  выходе (персистентность последней позиции).
- Педы-призраки бессмертны и умирают только когда умирает их оригинал; труп
  со снаряжением остаётся.

## Требования

- **Red Dead Redemption 2** для PC, билд **1.0.1491.50** (только Story Mode).
- **ScriptHookRDR2.dll** (V2 2.0 / Alex Blade) рядом с `RDR2.exe`.
- **ASI-лоадер** (`dinput8.dll` / `dsound.dll`) в папке игры.
- Компилятор: **Visual Studio 2019 Build Tools** (MSVC x64) + CMake.

## Сборка

```
cmake -S . -B build -G "Visual Studio 16 2019" -A x64
cmake --build build --config Release
```

Результат — `build/Release/rdr2_coop.asi`.

## Установка

1. Положи `rdr2_coop.asi` в `E:\Games\Red Dead Redemption 2\scripts\`
   (папку `scripts` создать, если нет).
2. Убедись, что в корне игры есть `ScriptHookRDR2.dll` и ASI-лоадер.
3. Запусти игру → Сюжет. Лог — `scripts\rdr2-coop.log`.

> Без `ScriptHookRDR2.dll` плагин не загрузится; в логе будет
> `ScriptHookRDR2.dll not found`.

## Как устроено

- `src/main.cpp` — `DllMain` + цикл скрипта (`ScriptMain`).
- `src/script_hook.cpp/h` — резолв экспортов `ScriptHookRDR2.dll`
  (`scriptRegister`, `nativeInit`, `nativePush64`, `nativeCall`, `scriptWait`)
  через `GetProcAddress`/поиск по PE-экспортам. Проприетарный SDK не нужен.
- `src/native_call.h` — обёртка вызова нативов + маршаллинг `Vec3`.
- `src/natives.h` — проверенные хэши нативов (из `Disquse/rdr3noclip`).
- `src/ghost_frame.h` — контейнер состояния удалённого игрока
  (`GhostFrame`: позиция, поворот, анимация, `seq`).
- `src/coop.cpp` — логика спавна/метки/имени педа, эмуляция подключения.
- `src/log.cpp/h` — единый логгер в папку плагина.
- `third_party/` — справочные исходники (rdr3noclip, nativedb, runtime).

## Экспорты ScriptHookRDR2

Плагин ищет экспорты по PE-экспортной таблице с матчингом токена (`strstr`),
т.к. благ V2 экспортирует функции под мангл-именами (`?scriptRegister@@...`).

Ключевая находка для спавна педа: **человеческий пед становится видимым только
после обвязки** `SET_ENTITY_AS_MISSION_ENTITY` + `SET_PED_RANDOM_COMPONENT_VARIATION`
+ `SET_ENTITY_VISIBLE`. Иначе пед создаётся, но не рендерится.
